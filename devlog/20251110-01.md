# 2025-11-10 (7일차)

## 프로모션 안내 기능 구현 준비

어제 장바구니 기능을 만들면서 기본적인 상품 담기와 가격 계산은 완성했다. 오늘은 원본 미션의 핵심 기능 중 하나인 프로모션 안내를 구현하기로 했다.

원본 콘솔 미션을 보면 두 가지 안내가 있다. 첫 번째는 추가 증정 안내다. 사용자가 콜라를 2개 담았는데, 2+1 프로모션이 있으면 "현재 콜라는 1개를 무료로 더 받을 수 있습니다. 추가하시겠습니까?"라고 물어본다. 두 번째는 정가 결제 확인이다. 프로모션 재고가 10개인데 13개를 담으려고 하면, "현재 콜라 4개는 프로모션 할인이 적용되지 않습니다. 그래도 구매하시겠습니까?"라고 확인받는다.

웹 UI에서는 이걸 모달로 구현하면 될 것 같다. 상품을 담을 때 이런 상황이면 모달을 띄워서 사용자에게 선택권을 주는 방식이다.

## 모달을 띄우려면 판단 로직이 먼저 필요하다

모달을 만들기 전에 먼저 해야 할 일이 있다. 언제 모달을 띄워야 하는지 판단하는 로직이다.

추가 증정이 가능한지 어떻게 알 수 있을까? 콜라 2+1 프로모션이 있고, 사용자가 2개를 담으려고 한다고 가정하자. 프로모션 재고가 충분하다면 3개를 만들 수 있으니 추가 증정이 가능하다. 하지만 2개를 담으려는데 프로모션 재고가 정확히 2개만 남았다면? 1개를 더 줄 수 없으니 추가 증정 불가능이다. 또 하나 중요한 건, 사용자가 2개가 아니라 3개나 4개를 담으려고 하면? 이미 프로모션 세트를 완성했거나 넘어선 상태니까 추가 증정 안내를 할 필요가 없다.

정가 결제 수량은 어떻게 계산할까? 콜라 2+1, 프로모션 재고 10개, 사용자가 13개를 담으려고 한다고 가정하자. 프로모션 재고 10개로는 최대 3세트를 만들 수 있다. 3세트면 9개다. 남은 1개는 프로모션 적용이 안 된다. 그런데 사용자는 13개를 원한다. 9개는 프로모션, 4개는 정가 결제다. 따라서 정가 결제 수량은 4개다.

## Inventory 클래스에 판단 로직 추가

이런 판단 로직을 어디에 넣어야 할까? 재고 상황을 알아야 판단할 수 있다. 프로모션 재고가 몇 개 남았는지, 일반 재고는 몇 개인지 파악해야 한다. 재고 정보를 가지고 있는 건 Inventory 클래스다. 그래서 Inventory에 두 가지 메서드를 추가하기로 했다.

```typescript
canGetAdditionalFreeItem(name: string, quantity: number, promotion: Promotion, promotions: Promotion[]): boolean

calculateFullPriceQuantity(name: string, quantity: number, promotion: Promotion, promotions: Promotion[]): number
```

첫 번째 메서드는 추가 증정이 가능한지 boolean으로 반환한다. 두 번째 메서드는 정가로 결제해야 하는 수량을 숫자로 반환한다. 프로모션이 전부 적용되면 0을 반환한다.

## canGetAdditionalFreeItem 구현

```typescript
canGetAdditionalFreeItem(name: string, quantity: number, promotion: Promotion, promotions: Promotion[]): boolean {
  const promotionStock = this.getPromotionStock(name, promotions)
  const setQuantity = promotion.getTotalQuantity()
  const remainder = quantity % setQuantity

  if (remainder !== promotion.buy) {
    return false
  }

  return promotionStock >= quantity + promotion.get
}
```

로직을 단계별로 설명하면 이렇다. 먼저 프로모션 재고를 확인한다. `getPromotionStock`은 이미 구현되어 있는 메서드다. 프로모션 세트 수량을 구한다. 2+1이면 3, 1+1이면 2다. `Promotion.getTotalQuantity()`가 이걸 반환한다. 사용자가 담으려는 수량을 세트 수량으로 나눈 나머지를 구한다. 2+1에서 2개를 담으면 나머지는 2다. 5개를 담으면 나머지는 2다. 3개나 6개를 담으면 나머지는 0이다.

나머지가 `promotion.buy`와 정확히 일치해야 추가 증정 가능이다. 2+1에서 나머지가 2면 1개를 더 받아서 3개 세트를 완성할 수 있다. 나머지가 0이면 이미 세트가 완성된 상태니까 추가 증정 의미가 없다. 마지막으로 프로모션 재고가 충분한지 확인한다. 현재 수량에 증정 수량을 더한 만큼의 재고가 있어야 한다. 2개를 담고 1개를 더 받으려면 프로모션 재고가 최소 3개는 있어야 한다.

## calculateFullPriceQuantity 구현

```typescript
calculateFullPriceQuantity(name: string, quantity: number, promotion: Promotion, promotions: Promotion[]): number {
  const promotionStock = this.getPromotionStock(name, promotions)
  const setQuantity = promotion.getTotalQuantity()
  const maxSets = Math.floor(promotionStock / setQuantity)
  const maxPromotionQuantity = maxSets * setQuantity

  return Math.max(0, quantity - maxPromotionQuantity)
}
```

이 메서드도 단계별로 보자. 프로모션 재고를 확인한다. 프로모션 재고로 만들 수 있는 최대 세트 수를 계산한다. 2+1에서 재고가 10개면 3세트까지 가능하다. 10을 3으로 나눈 몫은 3이다. 최대 세트 수에 세트 수량을 곱하면 프로모션으로 담을 수 있는 최대 수량이다. 3세트 × 3개 = 9개다. 사용자가 원하는 수량에서 프로모션 최대 수량을 빼면 정가 결제 수량이다. 13개 - 9개 = 4개다.

`Math.max(0, ...)`을 쓴 이유는 음수가 나올 수 없기 때문이다. 프로모션 재고가 충분하면 정가 결제가 0개일 수 있다.

이제 판단 로직은 준비됐다. 다음은 이 로직을 사용해서 모달을 띄우는 기능을 만들 차례다. ProductTableRow에서 담기 버튼을 누를 때, 이 두 메서드를 호출해서 모달을 띄울지 말지 결정하면 된다. BaseModal 컴포넌트가 이미 만들어져 있으니까 이걸 활용해서 PromotionConfirmModal을 만들면 될 것 같다.
