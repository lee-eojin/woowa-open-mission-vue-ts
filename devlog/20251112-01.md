# 2025-11-12 (9일차)

## 멤버십 할인 기능 구현

오전에는 간단하게 상수 리팩토링을 마치고, 오후에는 다음 기능으로 넘어갔다. 원본 미션의 멤버십 할인 기능이다.
일단 오늘 구현해야 할 요구사항을 정리했다.

프로모션 미적용 금액의 30%를 할인한다. 최대 8,000원까지다. 사용자가 멤버십 사용 여부를 선택할 수 있어야 한다.

## 할인 계산 로직 설계

먼저 계산 방식을 명확히 해야 했다.

총금액이 20,000원이고 프로모션 할인이 3,000원이라고 가정하자. 프로모션 미적용 금액은 17,000원이다. 멤버십 할인은 17,000원의 30%인 5,100원이다. 하지만 최대 8,000원 제한이 있으니 5,100원 그대로 적용된다.

만약 프로모션 미적용 금액이 30,000원이면? 30%는 9,000원인데, 8,000원이 최대니까 8,000원만 할인한다.

로직을 코드로 옮기면 이렇다.

```typescript
getMembershipDiscount(useMembership: boolean): number {
  if (!useMembership) {
    return 0
  }

  const nonPromotionAmount = this.getTotalPrice() - this.getPromotionDiscount()
  const discount = nonPromotionAmount * 0.3

  return Math.min(discount, 8000)
}
```

0.3과 8000은 기능 구현 전부 했다싶으면 상수로 뺄 예정이다.

## 어디에 구현할까

멤버십 할인 계산을 어디에 둘지 고민했다. 선택지는 세 가지였다.

첫째, Cart 클래스에 메서드로 추가한다. getTotalPrice, getPromotionDiscount처럼 getMembershipDiscount를 만든다.

둘째, cartStore에서 computed로 계산한다. cart의 값들을 가져와서 store에서 계산한다.

셋째, CartSummary 컴포넌트에서 직접 계산한다. UI 레이어에서 계산 로직을 가진다.

세 번째는 바로 제외했다. 컴포넌트는 표시만 해야 한다. 비즈니스 로직을 컴포넌트에 넣으면 테스트하기 어렵고 재사용도 불가능하다.

두 번째도 개인적으로는 적합하지 않다고 판단했다. 할인 계산은 명백히 비즈니스 로직이다. store는 상태 관리만 해야 한다.

결국 첫 번째 방법을 선택했다. Cart 클래스에 getMembershipDiscount 메서드를 추가한다. 다른 가격 계산 메서드들과 같은 레이어에 있는 게 맞다.

## useMembership을 어떻게 처리할까

멤버십 할인 계산에는 사용자의 선택이 필요하다. 체크박스로 멤버십 사용 여부를 받아야 한다.

이것도 고민을 오래했다. Cart 클래스가 멤버십 사용 여부를 상태로 가져야 하나? 아니면 파라미터로 받아야 하나?

만약 Cart가 useMembership을 필드로 가진다면 이렇게 된다.

```typescript
class Cart {
  private useMembership: boolean = false

  setMembership(value: boolean) {
    this.useMembership = value
  }

  getFinalPrice(): number {
    return this.getTotalPrice() - this.getPromotionDiscount() - this.getMembershipDiscount()
  }

  getMembershipDiscount(): number {
    if (!this.useMembership) {
      return 0
    }
    // 계산...
  }
}
```

Cart가 멤버십 상태를 직접 관리한다. 문제는 이게 Cart의 본질적인 책임인가?

고민하다가 아니라는 결론을 내렸다. Cart는 장바구니 데이터를 관리한다. 상품 목록, 수량, 가격 계산이 핵심이다. 멤버십 사용 여부는 UI 상태에 가깝다. 사용자가 체크박스를 토글하는 행위다.

그래서 useMembership을 파라미터로 받기로 했다.

```typescript
getMembershipDiscount(useMembership: boolean): number {
  if (!useMembership) {
    return 0
  }
  // 계산...
}

getFinalPrice(useMembership: boolean = false): number {
  return this.getTotalPrice() - this.getPromotionDiscount() - this.getMembershipDiscount(useMembership)
}
```

이렇게 하면 Cart는 계산만 담당한다. 상태 관리는 외부에서 한다. 테스트할 때도 편하다. true를 넘기면 할인 적용, false를 넘기면 미적용이다.

## cartStore에 멤버십 상태 추가

useMembership 상태는 cartStore에 두기로 했다. 전역 상태로 관리해야 여러 컴포넌트에서 접근할 수 있다.

```typescript
const useMembership = ref(false)

const setMembership = (value: boolean) => {
  useMembership.value = value
}

const membershipDiscount = computed<number>(() => {
  if (!cart.value) return 0
  return cart.value.getMembershipDiscount(useMembership.value)
})

const finalPrice = computed<number>(() => {
  if (!cart.value) return 0
  return cart.value.getFinalPrice(useMembership.value)
})
```

useMembership이 변경되면 membershipDiscount와 finalPrice가 자동으로 재계산된다. Vue의 반응형 시스템이 알아서 처리해준다.

## CartSummary UI 구현

체크박스를 어디에 배치할지 고민했다. 금액 계산 흐름을 생각해보면 이렇다.

1. 총 금액
2. 프로모션 할인
3. 멤버십 할인
4. 최종 금액

프로모션 할인 다음에 멤버십 체크박스가 오는 게 자연스러운것같다. 사용자가 프로모션 할인을 확인하고 멤버십을 선택한다.

```vue
<div class="summary-row">
  <span>{{ UI_MESSAGES.CART.TOTAL_PRICE_LABEL }}</span>
  <span>{{ formatPrice(cartStore.totalPrice) }}{{ UI_MESSAGES.COMMON.CURRENCY_UNIT }}</span>
</div>

<div v-if="cartStore.promotionDiscount > 0" class="summary-row discount">
  <span>{{ UI_MESSAGES.CART.PROMOTION_DISCOUNT_LABEL }}</span>
  <span>-{{ formatPrice(cartStore.promotionDiscount) }}{{ UI_MESSAGES.COMMON.CURRENCY_UNIT }}</span>
</div>

<div class="membership-section">
  <label class="membership-checkbox">
    <input
      type="checkbox"
      :checked="cartStore.useMembership"
      @change="handleMembershipChange"
    />
    <span>{{ UI_MESSAGES.CART.MEMBERSHIP_LABEL }}</span>
  </label>
</div>

<div
  v-if="cartStore.useMembership && cartStore.membershipDiscount > 0"
  class="summary-row discount"
>
  <span>{{ UI_MESSAGES.CART.MEMBERSHIP_DISCOUNT_LABEL }}</span>
  <span>-{{ formatPrice(cartStore.membershipDiscount) }}{{ UI_MESSAGES.COMMON.CURRENCY_UNIT }}</span>
</div>
```

멤버십 할인 금액은 체크박스를 선택했고 할인이 0보다 클 때만 표시한다. 불필요한 정보를 숨긴다.

체크박스 이벤트 처리는 간단하다.

```typescript
const handleMembershipChange = (event: Event) => {
  const target = event.target as HTMLInputElement
  cartStore.setMembership(target.checked)
}
```

체크박스 상태를 읽어서 store에 전달한다. store가 업데이트되면 computed들이 재계산되고 UI가 갱신된다.

## 멤버십 상수 추가

0.3(30%)과 8000(최대 할인)도 상수로 빼야 한다고 생각했다. constants.ts에 MEMBERSHIP 섹션을 추가했다.

```typescript
MEMBERSHIP: {
  DISCOUNT_RATE: 0.3,
  MAX_DISCOUNT_AMOUNT: 8000,
}
```

Cart 클래스에서 이걸 사용하도록 수정했다.

```typescript
const discount = nonPromotionAmount * CONSTANTS.MEMBERSHIP.DISCOUNT_RATE
return Math.min(discount, CONSTANTS.MEMBERSHIP.MAX_DISCOUNT_AMOUNT)
```

나중에 할인율이나 한도가 바뀌면 상수만 수정하면 된다. 비즈니스 규칙 변경이 한 곳에 집중된다.

## 동작 확인

브라우저에서 테스트했다. 콜라 10개를 담았다. 2+1 프로모션으로 9개가 할인 적용되고 1개는 정가다. 총금액 10,000원, 프로모션 할인 3,000원이 표시됐다.

멤버십 체크박스를 클릭했다. 프로모션 미적용 금액은 7,000원이다. 30%는 2,100원이다. 멤버십 할인 행에 "-2,100원"이 나타났다. 최종 금액이 4,900원으로 변경됐다.

체크박스를 다시 해제하니 멤버십 할인이 사라지고 최종 금액이 7,000원으로 돌아왔다. 반응형 시스템이 정확하게 작동한다.

30,000원짜리 상품을 담아서 최대 한도를 테스트했다. 프로모션 없이 30,000원 전체가 멤버십 대상이다. 30%는 9,000원인데, 화면에는 "-8,000원"이 표시됐다. Math.min이 제대로 작동한다.

## 레이어별 책임 분리

오늘 구현한 구조를 정리해보면 꽤 명확하게 분리되어 있다.

도메인 레이어(Cart): 멤버십 할인 계산 로직. 비즈니스 규칙만 담당한다. 30% 계산, 8,000원 한도 체크.

상태 관리 레이어(cartStore): useMembership 상태 관리. computed로 할인 금액을 reactive하게 만든다.

UI 레이어(CartSummary): 체크박스 표시, 할인 금액 표시. 사용자 입력을 받아서 store로 전달한다.

각 레이어가 자기 책임만 가진다. 도메인은 Vue를 모르고, UI는 계산 로직을 모른다. 테스트하기도 쉽고 수정하기도 쉬운 구조다.

---

멤버십 할인 구현에서는 계산 로직을 어디에 둘지, 상태를 누가 관리할지 고민이 많았다. 결국 각 레이어의 책임을 명확히 하는 방향으로, 즉 Cart는 계산, store는 상태 관리, 컴포넌트는 표시로 결정했다.

useMembership을 Cart의 필드로 둘지 파라미터로 받을지도 고민했다. Cart의 본질적인 책임을 생각해보니 멤버십 사용 여부는 UI 상태에 가깝다고 판단했다. 파라미터로 받는 방식이 더 깔끔하고 테스트하기도 쉽다.

Vue의 반응형 시스템이 정말 강력하다는 걸 다시 한번 느꼈다. 체크박스 하나 토글하면 할인 금액, 최종 금액이 자동으로 갱신된다. 코드는 선언적이고 간결한데 동작은 완벽하다.
