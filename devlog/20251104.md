# 2025-11-04 (오픈미션 공개일)

## 배경

나는 재료공학과 출신 비전공자이다. 지금까지 JavaScript만 다뤄봤고, TypeScript나 프론트엔드 프레임워크는 한 번도 사용해본 적이 없다. 평소에도 실무에서 쓰이는 기술 스택을 한번이라도 경험해보고 싶었는데, 오픈미션이 좋은 기회가 될 수 있을 것 같았다.

## 오픈미션 선택

우테코 프리코스 4~5주차가 오픈미션으로 진행된다는 공지를 읽었다. 기존 1~3주차에서 계산기, 자동차 경주, 로또를 Vanilla JavaScript로 구현했는데, 모두 Console 기반의 입출력이었다. 클래스 설계, 유효성 검증, 단위 테스트 작성 등 객체지향적 사고를 연습하는 데 집중했지만, 실제 사용자가 보고 클릭할 수 있는 UI까지 만들어보고싶었다.

처음엔 당장 어제 완성했던 로또 미션을 Vue로 전환하는 것을 고려했다. 이미 구현해본 미션이라 로직을 이해하고 있었고, 한번도 해본 적 없는 UI 작업에도 집중할 수 있을 것 같았다. 당첨 결과를 시각화하거나 차트로 보여주는 등 프론트엔드다운 작업을 할 수 있다는 점이 매력적으로 다가왔다.

하지만 작년 4주차 미션인 편의점 POS를 보고 생각이 바뀌었다. 재고 관리, 프로모션 계산, 영수증 출력 등 실제 서비스에 가까운 복잡도를 가진 문제였고, 단순히 기능을 구현하는 것을 넘어 "어떻게 구조화할 것인가"를 고민할 수 있는 주제라고 생각했다. 로또보다 어려운 만큼 배울 것도 많을 거라는 확신이 들었다.

게다가 이왕 도전하는 거, Vue와 더불어서 (Vanilla JS가 아닌) TypeScript로 구현해보기로 했다. 실제 UI를 가진 웹 애플리케이션으로 만들면 프론트엔드 개발자로서 한 걸음 더 나아갈 수 있을 것 같았다. 새로운 도구를 배우는 건 부담이지만, 오픈미션의 취지가 "comfort zone을 벗어난 도전"이라는 점을 생각하면 지금이 기회라는 생각이 들었다.

## Vue.js 조사

프론트엔드 프레임워크로 Vue를 선택한 이유는 React보다 학습 곡선이 완만하다는 평가가 많았기 때문이다. 첫날이니만큼 공식 문서를 읽어보니 HTML 구조를 그대로 활용할 수 있고, 반응형 데이터 바인딩이 직관적이라는 점이 마음에 들었다. 2주라는 시간 안에 배우고 구현해야 하는 상황에서 빠르게 배울 수 있는 도구가 필요했다.

Vue 3의 Composition API가 함수형으로 상태를 관리한다는 점에서 재사용성이 높아 보였다. 특히 편의점 POS처럼 상품, 재고, 프로모션 등 여러 상태를 다뤄야 하는 프로젝트에 적합할 것 같다.

## TypeScript 조사

TypeScript를 처음 접하게 됐다. 타입을 명시해서 런타임 에러를 사전에 방지할 수 있다는 점이 큰 장점으로 보였다. 편의점 POS는 상품, 프로모션, 영수증 등 복잡한 데이터 구조를 다루기 때문에 타입 시스템이 있으면 실수를 줄일 수 있을 것 같다.

공식 문서에서 interface, type, 제네릭 같은 개념을 간단히 훑어봤는데, 결국 JavaScript에 타입만 추가된 것이라 생각보다 진입 장벽이 낮아 보였다. 기존에 쓰던 JavaScript 문법 그대로 쓰고, 필요한 부분에만 타입을 붙이면 되는 구조라 실제로 쓰면서 익숙해지면 될 것 같다.

## 기술 스택 결정

최종적으로 다음과 같은 스택으로 가기로 했다:

- Vue 3 (Composition API): 프론트엔드 프레임워크
- TypeScript: 타입 안정성
- Vite: 빠른 개발 서버
- Pinia: 상태 관리 (장바구니, 재고 등)
- Vitest: 테스트 도구
- Vue Router: 페이지 라우팅
- ESLint + Prettier: 코드 품질 관리

남은 시간에는 공식 문서로 공부를 하고나서, 내일부터 본격적으로 프로젝트를 시작할 예정이다.
