# 2025-11-12 (9일차) - 결제 및 영수증 기능

## 사용자 플로우 완성하기

사용자가 상품을 담고, 멤버십을 선택하고, 결제하면 영수증을 보여주는 플로우이다. 일단 원본 콘솔 미션에서는 영수증 출력이 핵심이었다.
반대로 웹 UI에서는 이걸 모달로 구현하면 자연스러울 것 같았다.

결제하기 버튼을 누르면 영수증 모달이 뜨고, 구매 내역과 증정품, 금액 요약을 보여준다. 확인 버튼을 누르면 장바구니가 초기화되고 다시 쇼핑할 수 있다.

## 증정품 계산 로직이 먼저 필요하다

영수증에는 증정품 목록이 들어가야 한다. 콜라 2+1 프로모션에서 6개를 담았다면 2세트가 완성되어서 2개를 무료로 받는다. 이 정보를 어디선가 계산해야 한다.

이미 프로모션 할인 금액은 Cart에서 계산하고 있었다. getPromotionDiscount 메서드가 그걸 한다. 증정품 개수도 비슷한 방식으로 계산하면 될 것 같았다.

Cart 클래스에 getFreeItems 메서드를 추가하기로 했다.

## getFreeItems 구현

증정품 개수를 계산하는 로직은 간단했다.

```typescript
getFreeItems(): { productName: string; quantity: number }[] {
  const freeItems: { productName: string; quantity: number }[] = []

  this.getItems().forEach((item) => {
    if (!item.promotion) return

    const setQuantity = item.promotion.getTotalQuantity()
    const sets = Math.floor(item.quantity / setQuantity)
    const freeQuantity = sets * item.promotion.get

    if (freeQuantity > 0) {
      freeItems.push({
        productName: item.product.name,
        quantity: freeQuantity
      })
    }
  })

  return freeItems
}
```

장바구니의 각 아이템을 순회하면서 프로모션이 있는지 확인한다. 프로모션이 없으면 증정품도 없다.

세트 수량(2+1이면 3)으로 구매 수량을 나눈 몫이 완성된 세트 개수다. 6개를 3으로 나누면 2세트다. 완성된 세트 개수에 증정 개수(2+1이면 1)를 곱하면 총 증정 수량이다. 2세트 × 1개 = 2개다.

증정 수량이 0보다 크면 배열에 추가한다. 상품명과 수량을 객체로 만들어서 반환한다.

이 메서드에서는 순수하게 계산만 한다. 도메인 로직이 Cart에 집중된다.

## cartStore에 노출

getFreeItems를 만들었으니 이제 cartStore에서도 접근할 수 있게 해야 한다. computed로 래핑했다.

```typescript
const freeItems = computed<{ productName: string; quantity: number }[]>(() => {
  if (!cart.value) return []
  return cart.value.getFreeItems()
})
```

cart가 변경되면 freeItems도 자동으로 재계산된다. 컴포넌트에서는 cartStore.freeItems를 참조하면 항상 최신 증정품 목록을 받는다.

영수증에는 총 구매 수량도 필요했다. 총구매액 옆에 표시되는 수량이다. 이것도 computed로 추가했다.

```typescript
const totalQuantity = computed<number>(() => {
  if (!cart.value) return 0
  return cart.value.getItems().reduce((sum, item) => sum + item.quantity, 0)
})
```

장바구니 아이템들의 수량을 전부 합산한다. 콜라 3개, 사이다 2개면 총 5개다.

## 영수증 메시지 상수 추가

영수증에 들어갈 텍스트들을 uiMessages.ts에 추가했다. RECEIPT 섹션을 만들고 필요한 메시지를 전부 정의했다.

"W 편의점", "구매 내역", "증정", "총구매액", "행사할인", "멤버십할인", "내실돈" 같은 것들이다. 원본 콘솔 미션의 출력 형식을 참고했다.

영수증은 다른 UI와 달리 정형화된 포맷이 있다. 특히 한국 영수증은 특정 용어를 많이 쓴다. "내실돈"이 대표적이다. 이런 도메인 용어를 상수로 관리하면 일관성이 유지된다.

## ReceiptModal 컴포넌트 설계

영수증 모달을 만들 차례다. 이미 BaseModal이 있으니 이걸 재사용하기로 했다. PromotionConfirmModal과 같은 패턴이다.

영수증 UI는 크게 네 부분으로 나눴다.

첫째, 헤더다. 가운데 정렬로 "W 편의점"을 크게 표시한다. 구분선으로 경계를 나눈다.

둘째, 구매 내역 섹션이다. 테이블 형식으로 상품명, 수량, 금액을 보여준다. 장바구니의 모든 아이템을 반복한다.

셋째, 증정 섹션이다. freeItems가 있을 때만 표시한다. v-if로 분기했다. 증정품이 없으면 이 섹션 자체가 렌더링되지 않는다. 테이블로 상품명과 수량을 표시한다. 금액은 안 적는다. 무료니까.

넷째, 금액 요약이다. 총구매액, 행사할인, 멤버십할인, 내실돈을 순서대로 나열한다. 할인은 0보다 클 때만 표시한다. v-if를 각각 걸었다.

```vue
<div v-if="cartStore.promotionDiscount > 0" class="summary-row">
  <span>{{ UI_MESSAGES.RECEIPT.PROMOTION_DISCOUNT_LABEL }}</span>
  <span></span>
  <span>-{{ formatPrice(cartStore.promotionDiscount) }}{{ UI_MESSAGES.COMMON.CURRENCY_UNIT }}</span>
</div>
```

총구매액 행은 조금 특별하다. 3개의 컬럼이 있다. 첫 번째는 "총구매액", 두 번째는 수량, 세 번째는 금액이다. Grid를 써서 정렬을 맞췄다.

```typescript
grid-template-columns: 1fr auto auto
```

첫 컬럼은 남은 공간 전부, 두 번째와 세 번째는 내용 크기만큼만 차지한다. 수량과 금액이 오른쪽 정렬된다.

## 영수증 느낌을 살리는 스타일

영수증은 보통 고정폭 폰트를 쓴다. 편의점 프린터에서 나오는 종이 영수증을 생각하면 된다. Courier New를 적용했다.

```css
.receipt-content {
  font-family: 'Courier New', monospace;
}
```

구분선도 중요하다. 섹션 사이는 점선(dashed)으로 나누고, 큰 구분은 실선으로 처리했다. border-bottom을 각 섹션에 적용했다.

최종 금액 행은 굵게 표시하고 위에 선을 그었다. 사용자의 시선이 여기로 가게 만든다.

```css
.summary-row.final {
  font-weight: bold;
  font-size: 1.1rem;
  border-top: 1px solid #333;
}
```

테이블의 수량과 금액 컬럼은 오른쪽 정렬이다. 숫자는 오른쪽 정렬이 읽기 편하다.

## 결제 플로우 연결

CartSummary에 결제 로직을 추가했다. isReceiptOpen이라는 ref를 만들어서 모달 표시 여부를 관리한다.

결제하기 버튼에 handleCheckout을 연결했다.

```typescript
const handleCheckout = () => {
  if (cartStore.isEmpty) {
    alert('장바구니가 비어있습니다.')
    return
  }
  isReceiptOpen.value = true
}
```

장바구니가 비어있으면 결제할 수 없다. alert으로 안내하고 return한다. 장바구니에 상품이 있으면 isReceiptOpen을 true로 만든다. 그러면 ReceiptModal이 렌더링된다.

영수증 확인 버튼을 누르면 handleReceiptClose가 호출된다.

```typescript
const handleReceiptClose = () => {
  isReceiptOpen.value = false
  cartStore.clear()
  cartStore.setMembership(false)
}
```

모달을 닫고, 장바구니를 비우고, 멤버십을 해제한다. 다음 쇼핑을 위해 초기 상태로 돌린다.

## 장바구니 초기화 타이밍 고민

장바구니를 언제 비울지 고민이 좀 있었다.

첫 번째 선택지는 결제 버튼을 누를 때 바로 비우는 것이다. handleCheckout에서 cartStore.clear()를 호출한다. 이렇게 하면 영수증이 뜨자마자 장바구니는 비어있다.

두 번째는 영수증 확인을 누를 때 비우는 것이다. 영수증을 보는 동안에는 장바구니 데이터가 유지된다.

두 번째를 선택했다. 이유는 영수증이 cartStore의 데이터를 참조하기 때문이다. cartStore.items, cartStore.freeItems, cartStore.totalPrice 같은 것들을 읽는다.

만약 결제 버튼을 누를 때 장바구니를 비우면 어떻게 될까? 영수증 모달이 열리는데 cartStore가 이미 비어있다. 영수증에 아무것도 안 나온다.

물론 영수증용 데이터를 따로 복사해둘 수도 있다. receiptData 같은 ref를 만들어서 결제 시점의 장바구니 스냅샷을 저장하는 것이다. 하지만 그러면 데이터가 중복된다. 같은 정보를 두 곳에서 관리하게 된다.

영수증을 보는 동안 장바구니가 유지되는 게 더 간단하다고 판단했다. 사용자가 영수증을 확인하고 확인 버튼을 눌러야 쇼핑이 완전히 종료되고 장바구니가 초기화된다. 이게 더 자연스러운 플로우다.

## BaseModal 재사용의 장점

오늘 작업하면서 BaseModal을 만들어둔 게 정말 유용하다고 느꼈다.

PromotionConfirmModal과 ReceiptModal 둘 다 BaseModal을 그대로 쓴다. 오버레이, 애니메이션, ESC 키 처리, 닫기 버튼 같은 기능이 전부 자동으로 따라온다.

각 모달은 자기만의 컨텐츠와 footer만 정의하면 된다. 공통 기능은 BaseModal이 처리하고, 차별화된 부분만 슬롯으로 채운다.

컴포넌트 재사용이 이런 건가 싶었다. 한 번 잘 만들어두면 여러 곳에서 쓸 수 있다. 일관성도 유지된다. 모든 모달의 동작 방식이 똑같다.

나중에 모달 디자인을 바꾸고 싶으면 BaseModal만 수정하면 된다. PromotionConfirmModal과 ReceiptModal은 손댈 필요가 없다.

## 전체 사용자 플로우 완성

이제 사용자가 할 수 있는 전체 플로우가 완성됐다.

1. 상품 목록에서 수량을 선택하고 담기 버튼을 누른다.
2. 프로모션 상황이면 모달이 뜨고, 추가 증정이나 정가 결제를 선택한다.
3. 장바구니에 상품이 담긴다. 총 금액과 프로모션 할인이 표시된다.
4. 멤버십 체크박스를 선택하면 멤버십 할인이 추가로 적용된다.
5. 결제하기 버튼을 누르면 영수증 모달이 나타난다.
6. 구매 내역, 증정품, 금액 요약을 확인한다.
7. 확인 버튼을 누르면 장바구니가 초기화되고 다시 처음부터 시작한다.

원본 콘솔 미션의 핵심 기능이 웹 UI로 전부 구현됐다. 재고 관리, 프로모션 계산, 멤버십 할인, 영수증 출력까지.

결제 및 영수증 기능을 구현하면서 증정품 계산을 어디에 둘지 고민했다. 결국 도메인 로직은 Cart에, 상태 관리는 cartStore에, UI는 컴포넌트에 두는 패턴을 계속 유지했다. 레이어 분리가 일관되게 적용된다.

영수증 UI 디자인에서는 실제 종이 영수증을 참고했다. Courier New 폰트, 점선 구분, 오른쪽 정렬된 금액. 작은 디테일들이 모여서 영수증 느낌을 만든다.

장바구니 초기화 타이밍도 고민했다. 영수증이 cartStore를 참조하기 때문에 영수증 확인 시점에 비우는 게 가장 간단했다. 데이터 중복을 피할 수 있다.

BaseModal 재사용이 정말 강력하다는 걸 체감했다. 한 번 잘 만들어두면 여러 모달에서 활용할 수 있다. 컴포넌트 설계의 중요성을 다시 느꼈다.
